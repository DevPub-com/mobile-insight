# 대시보드 조회 분리와 리뷰 전체 집계

## 변경 범위

- 조회 목적에 따라 repository의 테이블 조회를 선택한다. 릴리스·동기화 상태·활성 사용자 API는 앱 확인 후 각각 필요한 테이블만 읽는다.
- 초기 화면에는 리뷰 전체 배열을 보내지 않는다. 서버가 기존 계산 함수를 사용해 기간 요약·평점 분포·VOC 건수와 화면에 필요한 대표 리뷰만 만든다.
- 기간 변경은 `/api/dashboard/{appCode}/view?from=...&to=...`에서 동일한 계산 결과를 받는다. 데이터 요청 중에는 이전 기간 숫자를 새 기간의 값으로 표시하지 않는다.
- 분석에 필요한 리뷰는 현재 기간, 이전 비교 기간, 최신 릴리스와 이전 릴리스 기간까지 조회한다. 기존 5,000건 제한을 적용하지 않는다.
- 리뷰 목록은 DB에서 필터링·페이지 조회하고 전체 건수는 별도 COUNT로 계산한다. `(reviewedAt DESC, id DESC)` cursor를 사용해 같은 작성 시각도 안정적으로 순회한다. 기존 page/pageSize/total/totalPages 응답과 page 요청도 지원한다.
- 리뷰 본문·작성자·기기·AI 토픽 변환을 한 mapper로 공유한다. 키워드 중복 경로는 EXISTS 조건으로 처리해 한 리뷰를 중복 집계하지 않는다.
- 배포 영향 화면은 저장 데이터와 Firebase 조회를 분리한다. Firebase 조회 실패가 저장된 리뷰·다운로드 값까지 없애지 않도록 저장 데이터 응답을 먼저 확보한다.

DB schema, 저장 데이터, 수집·upsert, 지표 계산식, 기간·반올림·결측값 정책은 변경하지 않았다. 5,000건 초과로 종전에 잘렸던 데이터의 집계는 이제 전체 대상 리뷰를 포함하므로 과거의 잘린 결과와는 다를 수 있다.

## 검증

- PGlite에 현재 migration을 적용하고 리뷰 5,006건으로 검증했다. 기간 내 5,003건, 부정 리뷰 2,001건이 집계되며 과거 릴리스 리뷰도 비교에 포함된다.
- 전체 원본 계산과 조회 범위를 줄인 서버 계산을 여러 기간에서 deep equality로 비교했다. 다운로드·Overview·활성 사용자·배포 영향의 조회 프로필별 출력도 비교했다.
- 전체 리뷰를 페이지 순회해 5,006개 ID의 누락·중복이 없음을 확인했다. 동일 작성 시각, 마지막 page, 날짜 끝 시각, 키워드·감정·평점·플랫폼 조합을 검증했다.
- 기존 데이터로 만든 대시보드와 리뷰 배열 없이 서버 집계를 전달한 대시보드의 초기 렌더링 HTML이 동일함을 확인했다.
- 입력 오류, 조회 가능 기간, Firebase 없이 저장 지표 반환, 지연 로딩 중 잘못된 0건 표시 방지를 검사했다.

실행 결과: 전체 테스트 460개 중 459개 통과. 작업 전부터 있던 `koboyo-icons.test.ts`의 `shield-alert` 소스 문자열 기대 1건은 실패한다. 타입 검사와 production build는 통과했으며 lint는 기존 미사용 변수 경고 2건이다.

실제 DB에 대한 읽기 전용 비교는 연결 또는 조회 실패로 완료하지 못했다. 운영 데이터 일치와 실제 응답 시간 개선을 측정했다고 주장하지 않는다. 브라우저 상호작용 E2E는 미실행이다.

## 남은 범위

이번에는 기존 숫자 보존을 우선해 계산 함수를 재사용한다. 서버의 상세 분석은 해당 원본 리뷰를 읽어 계산하며 SQL 사전 집계로 대체하지 않았다. 기본 다운로드·관측 시계열도 기존 비교 기준과 누적값을 보존하기 위해 유지한다. 프로덕션 트래픽과 데이터 규모를 측정한 뒤 SQL 집계·추가 인덱스·캐시를 검토할 수 있다.

공개 접근 정책과 배치 동기화 인증은 변경하지 않았다. 배포·커밋은 수행하지 않았다.
